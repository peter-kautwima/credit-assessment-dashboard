# Core dashboard review

Fresh read-only review of commit `49f1fdf`. Reviewer disposition: **fix core**.

## Findings

### P1 — stale evidence can cross a selection boundary

`useAssessmentDetails` retains successful resource state until the next effect runs. The first
render after selecting business B can therefore pair B's identity with business A's score,
financials, categories and attention reason.

Fix: key the file sheet by assessment id or key stored detail state to the assessment id. Add a
regression that resolves A, switches to pending B, and asserts A's evidence disappears immediately.

### P1 — mobile detail navigation loses focus

Selecting a row hides the focused docket without focusing the detail. Returning hides the focused
detail without restoring the originating row.

Fix: focus the detail heading after opening; restore focus to the originating docket row on return.
Test both directions.

### P1 — filtering can leave a hidden file open

Filters live inside `Docket`, while selection is resolved from the unfiltered collection. A Pending
filter can show one Pending row beside a Complete file that is no longer in view.

Fix: report visible ids to the workspace and move selection to the first visible file when the
current selection leaves the composed set. Add a Complete-to-Pending regression.

### P2 — mobile fetches the default file before it is opened

The first file is selected on load and the file sheet is hidden only with CSS, so its detail hooks
still fetch while mobile users remain on the docket.

Fix: gate detail mounting behind the mobile open state while retaining the desktop workspace.

### P2 — missing thin-file evidence becomes an affirmative claim

The current truthy branch maps a null or absent `isThinFile` value to “Established file”.

Fix: distinguish true, false and nullish values. Add a partial-report regression.

## Evidence that held

- Pending score and financial values use explicit null checks and never coerce to zero.
- Docket and detail endpoints preserve list-then-detail; failed cached requests are evicted.
- Docket and each detail panel implement loading, error, empty and success.
- Display-scale assumptions are disclosed on their artifacts.
- Attention follows the recorded High-risk-or-Pending rule.
- No test was found that literally cannot fail.

The reviewer ran read-only and changed no files. Its sandbox prevented Vite from creating its
temporary cache, so the writing session remains responsible for the full verification gate after
the fix batch.

## Fix verification

All five findings were addressed in one batch:

- The file sheet owns an assessment-keyed boundary, so old evidence unmounts before new identity
  renders. A direct rerender regression fails if that boundary is removed.
- Mobile focus moves to the detail heading and restores to the originating docket row.
- Filter events synchronously report their next composed ids, so selection moves in the same
  render when a filter removes the open file.
- Mobile detail resources do not mount until the analyst opens a file.
- Nullish thin-file evidence prints “Credit-file status not reported”.

Regression tests cover the stale-evidence boundary, synchronous filter selection, deferred mobile
requests, focus in both directions, and partial report data. `npm run verify` passes with 21 tests.
